CosmWasm security upgrade for passage-2 validators.

| Field | Value |

## Announcement Copy

The Passage v4.1.0 software upgrade patches a critical CosmWasm vulnerability (CWA-2026-006,
a Wasmer Singlepass sandbox escape that can lead to native token minting) and fixes issues
found since v4.0.0. Every validator must switch binaries at the upgrade height. The binary
ships with its libwasmvm library, and both files must be installed in the same directory.

## What Is Changing

- wasmd v0.50.0 to v0.54.10 and wasmvm v1.5.0 to v2.2.9: patches CWA-2026-006 and CWA-2026-005.
- Cosmos SDK v0.50.13 to v0.50.15 and ibc-go v8.0.0 to v8.8.0, as wasmd requires. The upgrade
  migrates the ibc module from version 5 to 6.
- Ledger and Amino-signed CosmWasm transactions are accepted again.
- `MsgClaim` is accepted again.
- Legacy governance proposals (text, x/params parameter change) are restored.
- The upgrade handler repairs duplicate account numbers (see below).
- wasm gas register and blocked-multisig ante fixes.
- No stores are added or removed. Contract code and state are preserved.

### Rehearsal on passage-2 state

The same commit, released as v4.1.0-rc1, was rehearsed on a copy of passage-2 state at height
21712866: the old binary halts at the upgrade height, the new binary runs the upgrade, the 33
code hashes and the raw state of the 79 contracts are unchanged, transactions and contract
queries work, and the node restarts. Report:
[REHEARSAL.md](https://github.com/envadiv/Passage3D/blob/v4.0.x/docs/v4.1.0-upgrade/REHEARSAL.md).

## Validator Instructions

### 1. Vote on the proposal

```bash
passage tx gov vote <proposal-id> yes \
  --from <key> \
  --chain-id passage-2 \
  --gas auto --gas-adjustment 1.5 --gas-prices 12.5upasg \
  --node <rpc> \
  -y
```

### 2. Download and verify the official Passage release

The release has, per architecture, a bundle (`.tar.gz`) with the binary, its libwasmvm library,
the provenance file and a checksum file.

```bash
V=4.1.0; ARCH=amd64     # or arm64
cd /tmp
curl -LO https://github.com/envadiv/Passage3D/releases/download/v$V/passage-$V-linux-$ARCH.tar.gz
```

linux/amd64:

```bash
echo "ba910ea6ce8e9ee9658ec4196a27f42452d671c67e1bdbe7a9c3850cddee0386  passage-4.1.0-linux-amd64.tar.gz" | sha256sum -c
```

linux/arm64:

```bash
echo "4a80b24ffdcac454f9e2ab185b04040ba4f6a21a77623a3af743f01e292f230b  passage-4.1.0-linux-arm64.tar.gz" | sha256sum -c
```

Extract and check:

```bash
mkdir -p /tmp/passage-$V && tar -xzf passage-$V-linux-$ARCH.tar.gz -C /tmp/passage-$V
(cd /tmp/passage-$V && sha256sum -c SHA256SUMS-$ARCH.txt)
/tmp/passage-$V/passage-$V-linux-$ARCH version                       # v4.1.0
/tmp/passage-$V/passage-$V-linux-$ARCH query wasm libwasmvm-version  # 2.2.9
```

**The binary needs its library.** `passage` loads `libwasmvm.x86_64.so` (`libwasmvm.aarch64.so`
on arm64) from its own directory. Keep both files together. The binary needs glibc 2.35 or
newer (Ubuntu 22.04 or later).

### 3. If using cosmovisor

Pre-stage **both files** before the upgrade height. Do not rely on automatic download: the
bundle has the binary at its root, not under `bin/`.

```bash
D=~/.passage/cosmovisor/upgrades/v4.1.0/bin
mkdir -p $D
cp /tmp/passage-$V/passage-$V-linux-$ARCH $D/passage
cp /tmp/passage-$V/libwasmvm.*.so $D/
$D/passage version && $D/passage query wasm libwasmvm-version
```

The directory name must be exactly `v4.1.0`.

### 4. If not using cosmovisor

Do not replace your running binary early. When the chain reaches the upgrade height, v4.0.3
halts with `UPGRADE "v4.1.0" NEEDED`. Then:

```bash
sudo systemctl stop passage
systemctl cat passage | grep ExecStart      # path of the binary, e.g. /usr/local/bin/passage
```

Install the binary and the library in the same directory. Replace `/usr/local/bin` if your
service uses a different path.

```bash
B=/usr/local/bin
sudo cp $B/passage $B/passage-pre-v4.1.0
sudo install -m 0755 /tmp/passage-$V/passage-$V-linux-$ARCH $B/passage
sudo install -m 0644 /tmp/passage-$V/libwasmvm.*.so $B/
$B/passage version                       # v4.1.0
$B/passage query wasm libwasmvm-version  # 2.2.9
sudo systemctl start passage
```

### 5. Back up at the upgrade height

Before starting v4.1.0, with the node stopped at the halt, copy `~/.passage/data` and
`~/.passage/wasm` (`cp -a --reflink=auto` or an LVM/ZFS/btrfs snapshot keeps it quick). Back up
`priv_validator_key.json` and `priv_validator_state.json` as well, and never run two instances
of the same validator. The backup is needed for a coordinated rollback.

### 6. Monitor after the upgrade

```bash
journalctl -u passage -f

passage version                                # v4.1.0
passage query wasm libwasmvm-version           # 2.2.9
passage q upgrade applied v4.1.0 --node <rpc>
passage status --node <rpc>
```

The first blocks can take longer while the new VM compiles the stored contracts again. Confirm
that the node is advancing, signing, and that peers reconnect.

## Important Notes

- The on-chain upgrade name is `v4.1.0`. The name is case-sensitive and must match exactly.
- Height is authoritative. Calendar estimates can drift with block time.
- Install the binary and `libwasmvm.<arch>.so` in the same directory.
- `minimum-gas-prices` in `app.toml` must be at least `12.5upasg`.
- Once v4.1.0 has committed blocks, reverting the binary alone is not safe. A rollback is
  coordinated by the team: all validators restore the backup and restart v4.0.3 with
  `--unsafe-skip-upgrades <height>`. Do not do it alone.
